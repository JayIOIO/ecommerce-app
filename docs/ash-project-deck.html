01 · The application

One storefront, three service boundaries

Buyer experience

Browse and search products, manage a cart, check out, and review orders.

Seller experience

Manage owned listings, see relevant orders, and update fulfillment status.

Service modules

Authentication, catalog/inventory, and order management share MySQL-backed data.

These features are present in the starter baseline. Contributions and final behavior must be attributed to the actual reviewed work, not assumed.

03 · Technology choices

Keep the stack aligned to the module boundaries

React + Vite

Component-based buyer/seller UI with a fast development server and a build-time static bundle.

Node.js + Express

Three independently organized APIs make authentication, catalog, and order ownership visible.

MySQL

Relational tables express users, products, orders, and item relationships.

Deployment tools

Docker, Compose, NGINX, and Jenkins are planned team-stage additions; include their rationale after review.

04 · User journeys

Two roles, different actions

Buyer path

Sign up / log in → search → cart → checkout → order history → cancel eligible pending order.

Seller path

Sign up / log in → create, edit, delete listing → view seller orders → advance fulfillment.
